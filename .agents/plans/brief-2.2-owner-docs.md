FACTS (the settings, exactly as they will ship; all are JVM system properties, e.g. -Dquicraft.admission.maxOpenPerIp=64, read at listener start):
- quicraft.admission.retry = adaptive (default) | always | never. adaptive: the server sends a QUIC Retry (address validation, costs the client one extra round trip and its 0-RTT early data) only once connection attempts in the current second reach retryThresholdPerSecond, or when an attempt is over a limit. always: every new connection gets a Retry (use under attack). never: no load-based Retry; over-limit attempts still get a Retry and then are dropped.

- quicraft.admission.ingressInitialsPerSecond = 4000 and ingressInitialsPerIpPerSecond = 200: a cheap packet-level guard that drops excess QUIC Initial datagrams before any QUIC processing. Other packets (established connections) are never counted.
- Invalid or out-of-range values fall back to the default with one WARNING in the log.
- A refused connection (over any attempt or open-connection limit) gets at most a Retry and is then silently dropped, before any QUIC connection exists; a QUICraft client falls back to TCP after its short head start (docs/protocol.md section 5). TCP joins are never limited by these settings.
- Retry tokens: HMAC-SHA256, bound to client IP and port, 30 s lifetime, key random per listener start (a restart invalidates outstanding tokens; harmless).
