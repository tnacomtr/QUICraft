STEPS:
1. `StateCodec`: `static byte[] encode(StateRecords.UpdaterState s)` and `static StateRecords.UpdaterState decode(byte[] bytes) throws UpdateRejectedException`.
   - Wire format exactly as `docs/updater.md` state.json example: header `"type":"quicraft.updater-state","v":1`, then fields. Empty seed values: revocations.sha256 "", issued "", expires "" (empty strings, not null). Timestamps `YYYY-MM-DDTHH:MM:SSZ` (use the same formatter as DocumentParser; Instants with nanos are rejected at encode with IllegalArgumentException).
   - Encoding is deterministic: keys written in a fixed order (sorted lexicographically at every level), no whitespace, UTF-8, strings escaped per JSON (only ASCII will appear; still escape `"` and `\\` and control chars). Write a small private JSON writer; no library.
   - Decode: StrictJson.parse(bytes, 131072, 4096); exact keys at every level (unknown or missing -> reject); cardinality caps from the schema table: seqByKid 0..32, withdrawn 0..256, warnedBad 0..32, tornSince keys only modrinth/github/sudoe; build records (IllegalArgumentException from a record constructor -> UpdateRejectedException("invalid state")).
   - Encoded size > 131072 -> encode throws IllegalStateException("state full") (callers treat as "state full", spec growth policy).
2. `RevokedCodec`: same for `revoked.json` (schema at docs/updater.md ~760-768: header type — copy the exact `type` string from the spec, grep for "quicraft.updater-revoked" or the revoked.json example; fields revokedKeys 0..64 of {kid,pub} with kid == Hex.kid(pub), blockedArtifacts 0..1024 of 128-hex). Cap 262144.
3. `StateStore` (final class), constructor `StateStore(Path updateDir)`. Files: `state.json`, `revoked.json`, `.prev` copies, `state.lock`.
   - In-process guard: a static `ConcurrentHashMap<Path, ReentrantLock>` keyed by `updateDir.toRealPath()`; take it BEFORE the OS lock (a second FileChannel.lock on the same file in one JVM throws OverlappingFileLockException).
   - OS lock: open `state.lock` with CREATE, WRITE, and `LinkOption.NOFOLLOW_LINKS`; `tryLock()`; null -> throw `StoreBusyException` (new checked exception extending UpdateRejectedException, message "another server uses this update directory"). Never block waiting for another process.
   - `Optional<StateRecords.Snapshot> load()`: under both locks, read and decode both files with the corruption rules below.
   - `StateRecords.Snapshot initialiseIfAbsent(StateRecords.StateDelta initial)`: under the locks, if neither file exists write revoked then state; if exactly one exists or either is corrupt follow the corruption rules; return the loaded snapshot.
   - `StateRecords.Snapshot commit(UnaryOperator<StateRecords.Snapshot> merge)`: under the locks: load current (must exist, else IllegalStateException), apply merge, if result equals current do nothing, else write `revoked.json` first then `state.json` (skip a file whose content did not change); return the new snapshot.
   - `StateRecords.Snapshot resetState(StateRecords.UpdaterState rebuilt)`: under the locks: requires a valid revoked.json (current or .prev) else throw UpdateRejectedException("revoked.json invalid; refetch required"); write only state.json from `rebuilt`; never touch revoked.json.
   - Atomic write of one file `<name>`: write `<name>.tmp` (CREATE, TRUNCATE_EXISTING, WRITE, NOFOLLOW_LINKS), `FileChannel.force(true)`, if `<name>` exists copy it to `<name>.prev` via the same tmp+force+ATOMIC_MOVE procedure (`<name>.prev.tmp`), then `Files.move(tmp, target, ATOMIC_MOVE)`, then fsync the directory (open the directory with FileChannel.open(dir, READ) and force(true); catch IOException on platforms that refuse and ignore it with a comment).
   - Corruption (per file): if `<name>` is missing or fails decode and `<name>.prev` decodes, use `.prev` and record a warning (expose `List<String> warnings()` of the last operation, fixed messages, no file content). If both invalid: for state.json -> snapshot unavailable, throw `StateUnavailableException` (checked, subclass of UpdateRejectedException) with field `boolean revokedValid`; for revoked.json the same exception with revokedValid=false. Callers decide disable-staging vs disable-updater. Never silently reset.
   - Clamp after `.prev` fallback: provide `static StateRecords.UpdaterState clampToTrust(StateRecords.UpdaterState s, UpdateDocuments.Trust trust)` that raises revocations.seq to >= trust.revocationsSeqFloor and minManifestSeq to >= trust.manifestSeqFloor without changing sha256/issued/expires (if seq is raised above the stored seq while sha256 is non-empty, reset to the seed form: sha256 "", issued/expires null). Pure; tested.
   - Filesystem safety: refuse (UpdateRejectedException) if `updateDir` or any of the files is a symlink (`Files.isSymbolicLink`, `NOFOLLOW_LINKS` reads). On POSIX file stores create the dir with `PosixFilePermissions.fromString("rwx------")` and files `rw-------`; skip permission setting when the store does not support POSIX (Windows), with a comment.
4. Tests (`StateCodecTest`, `RevokedCodecTest`, `StateStoreTest`, use `@TempDir`):
   - Round-trip equality; deterministic bytes (encode twice equal; encode(decode(x)) == x); key order sorted; seed form round-trips with empty strings; unknown key, missing key, wrong type, wrong v, over-cap arrays, over-size bytes rejected; kid not matching pub rejected in revoked.
   - Store: initialise writes both; commit writes revoked before state (simulate crash: write a test-only subclass or a package-private hook `Runnable afterRevokedWrite` that throws; after the "crash" a new StateStore load sees the new revoked + old state, and the next commit converges); corrupt state.json -> .prev used + warning; both state copies corrupt -> StateUnavailableException(revokedValid=true); both revoked copies corrupt -> revokedValid=false; resetState keeps revoked.json byte-identical; resetState refuses when revoked invalid; two threads committing concurrently in one JVM are serialised (no OverlappingFileLockException; final state contains both merges, e.g. two different kids added); a lock held by another process: simulate by opening a second FileChannel in a NEW thread is not enough (same JVM) — instead spawn a child JVM with ProcessBuilder (`ProcessHandle.current().info().command()` gives java path) running a tiny main class from test classes that holds the lock and prints "locked", then assert StoreBusyException; symlinked updateDir and symlinked state.json refused; POSIX permissions 700/600 when supported; clampToTrust cases.
