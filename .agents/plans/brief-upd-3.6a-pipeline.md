1. `CheckResult(CheckMode mode, Optional<AcceptedCandidate> candidate, boolean stateFull, boolean freshRevocations, List<String> diagnostics)` record.
2. `final class CheckPipeline` constructor `(StateStore store, MetadataCollector collector, ReleaseHosts hosts, RuntimeIdentity identity, Clock clock)`; method `CheckResult run(CheckMode mode, UpdateVersion onDiskVersion, CancelToken cancel) throws IOException, UpdateRejectedException`:
   a. revocationResponses = collector.collectRevocations(hosts, cancel)   (NO lock held during network)
   b. store.commit(snap -> Acceptance.evaluateRevocations(revocationResponses, hosts, snap, identity.runningTrust(), clock.instant()).delta() applied)   — the evaluation runs INSIDE commit on the freshly read snapshot; keep its diagnostics (capture via a local holder).
   c. manifestResponses = collector.collectManifests(hosts, cancel)   (no lock)
   d. store.commit(snap -> Acceptance.evaluateManifests(revocationResponses, manifestResponses, hosts, snap, identity, onDiskVersion, mode, clock.instant()) ...) — capture candidate/stateFull/diagnostics from the evaluation made inside the commit (the candidate must come from that same evaluation, not a second one).
   e. return CheckResult. A cancelled token before b or d returns an empty result with diagnostic "cancelled" and no commit.
   The state must already be initialised (caller's job at init); if not, IllegalStateException.
3. `final class UpdateAdmission` with `AdmissionContext(boolean initComplete, boolean journalPresent, String liveSha512AtInit, String currentLiveSha512, boolean stateFull)` record and `static AdmissionDecision admit(AdmissionContext ctx, RuntimeIdentity id, StateRecords.Snapshot current)`; `AdmissionDecision(boolean admitted, List<String> reasons)`. Refuse (all reasons collected, fixed texts) when: !initComplete; journalPresent ("a previous update is pending restart or recovery"); currentLiveSha512 != liveSha512AtInit ("the installed jar changed since start"); TrustTransition.classify(current.state().persistedTrust(), id.runningTrust()) is OLDER_EPOCH_REPORT_ONLY or INVALID_SAME_EPOCH; stateFull ("updater state full").
4. `final class StateReset` with `static ResetResult resetStateAndRefetch(StateStore store, CheckPipeline pipeline, RuntimeIdentity id, UpdateVersion onDiskVersion, CancelToken cancel)`; `ResetResult(boolean stateReset, boolean stagingEnabled, List<String> messages)`:
   - Build the seed state from TrustTransition.apply(classify(null, trust), trust, null).newState().
   - If revoked.json is valid (store.load() works or StateUnavailableException.revokedValid() is true): store.resetState(seed) (keeps revoked.json byte-identical), then pipeline.run(REPORT, ...) to refetch; stagingEnabled = result.freshRevocations().
   - If revoked.json is invalid (both copies): DO NOT write anything; return stateReset=false, stagingEnabled=false, message "revoked.json is unreadable; restore it from a backup or reinstall; the updater stays disabled" (spec 12.8 says re-merge every fetchable document; that needs a revoked-rebuild store API which is deferred — report this gap explicitly in your report as a deviation).
